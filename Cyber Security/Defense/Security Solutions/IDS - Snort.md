**IDS (Intrusion Detection System)** is a security solution inside the network to detect intrusion after the firewall. It monitors traffic based on its signature and anomaly-based detections, and detects any abnormal traffic going out or inside the network. It can generate alerts as well. IDS **does not** act on these detections though. Only notifies the security administrators about the activities.

## Types of IDS
- **HIDS:** Host Intrustion Detection System. Host-based, provide detailed visibility of the host's activity.
- **NIDS:** Network Intrusion Detection System. Network-based, added layer after firewall to branchout to different hosts. Monitor the network traffic of all the hosts involved to detect sus activities.

## Detection Modes
- **Signature-Based IDS:** Each attack has its unique pattern, known as signature. After an attack happened, IDS can perserve the signatures in the DB so if future attack happens, it can detect it by its signature. Unable to prevent zero-day attacks.
- **Anomaly-Based IDS:** First learns the normal behaviour (baseline) of the network or system. Then perform detections if there is any deviation from the baseline. Can detect zero-day attacks because not relying on signatures. Can be fine-tuned to reduce false positives.
- **Hybrid IDS:** Combines both methods.
## SNORT
Is one of the most widely used **open-source** IDS solution. Uses hybrid IDS.Threats are defined in the rule files of the Snort tool.
### Modes of Snort
| Mode                                    | Description                                                                                                                     | Use Case                                                                                                        |
| --------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------- |
| Packet sniffer mode                     | Reads and displays network packets without performing any analysis on them.                                                     | When network issues and need a detailed insights into the traffic.                                              |
| Packet logging mode                     | Perform logging into a PCAP format files. Includes all network traffic and any detections from it.                              | During forensic investigation of an attack. Logs generated by Snort can be used to perform root cause analysis. |
| Network Intrusion Detection System mode | Primary mode. Monitors all traffic in real-time and applies rule files to identify threats by signatures, then generate alerts. | Security team leverage Snort's NIDS mode to monitor network or systems to detect threats.                       |
### Rule Format
![[Pasted image 20261010143753.png]]
- **Action:** specifies action to take when the rule triggers.
- **Protocol:** protocol that matches this rule.
- **Source IP:** Origin IP traffic.
- **Destination IP:** Destination IP traffic.
- **Rule metadata:** metadata for rules
	- **Message (msg):** message displayed
	- **Signature ID (sid):** Identifier for the rule
	- **Rule revision (rev):** Revision number for the rule. For tracking changes in this rule.
### Rule Creation
From the "local.rules"
```shell-session
ubuntu@tryhackme:~$ sudo nano /etc/snort/rules/local.rules
```
Add rules:
`alert icmp any any -> 127.0.0.1 any (msg:"Loopback Ping Detected"; sid:10003; rev:1;)`
### Rule Testing
Starting Snort tool:
```shell-session
ubuntu@tryhackme:~$ sudo snort -q -l /var/log/snort -i lo -A alert_fast -c /etc/snort/snort.lua
```
note: replace "lo" with the correct interface name.
Test with ICMP packets to the loopback address:
```shell-session
ubuntu@tryhackme:~$ ping 127.0.0.1
```
Check the Snort-generated "Loopback Ping Detected" alert:
```shell-session
ubuntu@tryhackme:~$ sudo snort -q -l /var/log/snort -i lo -A alert_fast -c /etc/snort/snort.lua
07/24-10:46:52.401504  [**] [1:1000001:1] "Loopback Ping Detected" [**] [Priority: 0] {ICMP} 127.0.0.1 -> 127.0.0.1
07/24-10:46:53.406552  [**] [1:1000001:1] "Loopback Ping Detected" [**] [Priority: 0] {ICMP} 127.0.0.1 -> 127.0.0.1
```

### Running Snort on PCAP Files
This is for performing forensic investigation from a logged PCAP file and determine any signs of intrusion through that traffic.
```shell-session
ubuntu@tryhackme:~$ sudo snort -q -l /var/log/snort -r Task.pcap -A alert_fast -c /etc/snort/snort.lua
```
note: replace "Task.pcap" to the correct PCAP path file for analysis.
